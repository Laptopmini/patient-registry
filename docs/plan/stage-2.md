# Stage 2 brief: Backend (`backend-engineer`)

Scope: everything in `apps/api`. Don't touch `apps/web`, `docker-compose.yml` or CI; those belong to Stages 3 and 4.
Read first: `CLAUDE.md`, `docs/REQUIREMENTS.md`, ADRs 0001–0004 and 0009, and `design/brief/03-data-model.md` (field rules and enums). This brief adds to them and wins where they conflict.

## Layout (`apps/api/src/app/`)
`config.py` (pydantic-settings) · `db.py` (async engine, session dependency) · `models/` · `schemas/` · `services/` (no HTTP knowledge) · `routers/` · `summary/` (providers and cache) · `flags.py` (OpenFeature) · `errors.py` · `logging.py` · `seed.py` · `main.py` (app factory and lifespan) · `export_openapi.py`. Alembic lives at `apps/api/migrations/` with an async `env.py` and its URL taken from settings.

## Settings (all optional, so it starts with no `.env`)
`DATABASE_URL` (default `postgresql+asyncpg://registry:registry@localhost:5432/registry`) · `SEED_ON_STARTUP` (true) · `SEED_PATIENTS` (20) · `SEED_VALUE` (20261105) · `LOG_LEVEL` (INFO) · `LOG_FORMAT` (`json`|`console`, default json) · `FLAGD_HOST` (unset means OpenFeature uses the in-code defaults) · `FLAGD_PORT` (8013) · `ANTHROPIC_API_KEY` (`SecretStr | None`; wired only, unused until Stage 6).

## Data model (one initial Alembic migration, hand-reviewed)
- Enable the `pg_trgm` extension.
- Enums: `blood_type` (`A+ A- B+ B- AB+ AB- O+ O- unknown`, with Python enum member names that are valid identifiers) and `patient_status` (`active follow_up inactive`).
- `patients`: `id uuid pk` (generated by the app, uuid4), `first_name`, `last_name` (varchar 100), `date_of_birth date`, `email` and `phone` (nullable), address columns `address_line1/line2/city/region/postal_code/country` (nullable, with country as char(2)), `blood_type`, `status`, `version int not null default 1`, `created_at`, `updated_at` (timestamptz, server defaults), `archived_at timestamptz null`.
- `patient_allergies` and `patient_conditions`: `id`, `patient_id` FK `ON DELETE CASCADE`, `name varchar(100)`, with a unique index on `(patient_id, lower(name))`. Store them in input order (`position int`).
- `notes`: `id uuid pk`, `patient_id` FK `ON DELETE CASCADE`, `recorded_at timestamptz`, `body text`, `created_at timestamptz default now()`, with an index on `(patient_id, recorded_at DESC)`.
- Indexes, partial `WHERE archived_at IS NULL`: GIN trigram on `(first_name || ' ' || last_name)`, `email`, `phone`; btree on `lower(last_name), lower(first_name), id`; `date_of_birth`; `status`; `created_at`.
- `last_visit` is **never stored** (ADR 0001). Compute it with a correlated `MAX(recorded_at)` subquery, `NULLS LAST` when sorting.

## API (paths at the root, no prefix; every error is `application/problem+json`)
| Method and path | Success | Errors |
|---|---|---|
| `GET /health` | 200 `{"status":"ok"}` | — |
| `GET /patients` | 200 `{items, total, limit, offset}` | 422 |
| `POST /patients` | 201, `Location: /patients/{id}`, `ETag` | 422 |
| `GET /patients/{id}` | 200, `ETag` | 404, 422 (bad UUID) |
| `PUT /patients/{id}` | 200, new `ETag` | 404, 412, 422, **428 when `If-Match` is missing** |
| `DELETE /patients/{id}` | 204 (sets `archived_at`) | 404 (also for an already-archived patient); 412 if `If-Match` is given and stale |
| `GET /patients/{id}/notes` | 200 `{items}`, newest `recorded_at` first | 404 |
| `POST /patients/{id}/notes` | 201, `Location: /patients/{id}/notes/{note_id}` | 404, 422 |
| `GET /patients/{id}/notes/{note_id}` | 200 | 404 (including a note that belongs to another patient) |
| `DELETE /patients/{id}/notes/{note_id}` | 204 | 404 (same rule) |
| `GET /patients/{id}/summary` | 200 | 404 |

- **List query:** `q` (≤100 chars; ILIKE with escaped `%`/`_` across the full name, email and phone, so it uses the trigram indexes), `status`, `blood_type`, `condition` and `allergy` (case-insensitive exact match through `EXISTS`), `sort` from the allowlist `last_name, first_name, age, last_visit, created_at`, each optionally prefixed with `-` (default `last_name`; `age` sorts by `date_of_birth` reversed; always add `id` as a tiebreaker), `limit` 1–100 (default 20), `offset` ≥ 0. An unknown sort value gives 422. List items carry `id, first_name, last_name, date_of_birth, age, status, blood_type, last_visit`.
- **Patient body (POST and PUT, identical, since PUT is a full replacement):** `first_name`, `last_name` (trimmed, 1–100), `date_of_birth` (not in the future, at most 130 years ago), `email` (`EmailStr | None`), `phone` (`None` or valid E.164, normalized with `phonenumbers`), `address` (`None` or an object with `line1` and `city` required, `country` matching `^[A-Z]{2}$`, default `US`), `blood_type` (default `unknown`), `status` (default `active`), `allergies`/`conditions` (lists of `{name}`, at most 50 each, names 1–100 characters, case-insensitive duplicates rejected with 422). The response adds `id, age, last_visit, version, created_at, updated_at`. Treat the `age` calculation as a unit-tested pure function.
- **Concurrency:** `ETag: "<version>"`. `If-Match` must equal the current ETag, otherwise 412. A PUT bumps `version` and `updated_at` and replaces allergies and conditions in one transaction. Do the version check atomically: `UPDATE … WHERE id=:id AND version=:v`.
- **Notes:** `recorded_at` must include a timezone (naive gives 422) and can't be in the future (allow 60s of clock skew). `body` is trimmed, 1–5,000 characters.
- **Summary:** `{patient_id, name, age, blood_type, conditions, allergies, narrative, provider, note_count, generated_at}`. Identifiers and facts come from the database. Only `narrative` comes from a provider.
- **Errors:** handlers for `HTTPException`, `RequestValidationError` (422 with `errors: [{field: "address.city", message, type}]`, where `field` is a dotted path without the `body` prefix) and unhandled exceptions (500 with a generic message and no internals). Problem `type` is `about:blank` except for validation (`/problems/validation-error`) and the precondition errors (`/problems/precondition-failed`, `/problems/precondition-required`). Declare the error responses in OpenAPI (`responses=`) with a shared `Problem` model.

## Summary providers (`summary/`)
- A `SummaryProvider` protocol: `name: str`, `async generate(notes: Sequence[NoteForSummary]) -> str`. The model sees **notes only**, never identifiers.
- `TemplateProvider` (the default): a deterministic, coherent narrative of 1–3 short paragraphs. Cover the note count and date span, the most recent encounter (date and first sentence), and a brief chronology of earlier encounters. With no notes, return a fixed sentence.
- A registry chooses the provider: the `anthropic` provider only when the OpenFeature flag `summary-provider-anthropic` is true **and** a key is set. Stage 2 has no anthropic implementation, so it always falls back to the template, but keep the selection seam in place and tested.
- Cache: an in-process bounded LRU keyed by `sha256(provider name + each note's id, recorded_at and body)`.

## Feature flags (`flags.py`)
At startup, set the OpenFeature provider to flagd (`FLAGD_HOST`) when it's configured; otherwise leave the default no-op provider in place. Evaluate with defaults that are always safe (false). If flagd is unreachable, the app must still start.

## Logging
structlog JSON output. Middleware reads or creates `X-Request-ID`, echoes it in the response, and binds it to the context. It logs one `request` event per request with `method`, `path` (**no query string**, since search terms can be names), `status`, `duration_ms` and `request_id`. Never log bodies or patient fields. Add a test that asserts a search term never shows up in the logs.

## Seeding (`seed.py`, run from the lifespan when `SEED_ON_STARTUP` is true)
- Idempotent: inside a transaction holding `pg_advisory_xact_lock`, seed only when `patients` is empty.
- Use `Faker("en_US")` seeded with `SEED_VALUE` and generate `SEED_PATIENTS` patients. Emails use `@example.com`. Phones are E.164 in the fictional range `+1<area>55501NN`. Allergies and conditions come from small realistic lists. Use 0–6 notes per patient built from short clinical sentence templates, with `recorded_at` relative to *now* (the past 400 days). Make two of the first 20 patients have no notes, and give one a very long hyphenated name. Status weights: about 60% active, 20% follow_up, 20% inactive.
- Mark it synthetic: a module docstring and a log line `seeded synthetic patients count=N`.
- Must handle `SEED_PATIENTS=1000` in a few seconds (bulk inserts).

## OpenAPI export
`uv run python -m app.export_openapi` writes `apps/api/openapi.json` (sorted keys, 2-space indent, trailing newline). Commit the file. A pytest test fails when the committed file differs from the live schema. Give every route a stable `operation_id` (`list_patients`, `get_patient`, …) and tags.

## Tests (pytest, real Postgres through testcontainers `postgres:18.6-alpine`, session-scoped)
- Migrate the container with `alembic upgrade head` (also check a `downgrade base` and `upgrade head` round trip once). Isolate each test by truncating tables or rolling back.
- `tests/unit/`: age calculation, phone and email validation, the template narrative, the cache key, sort parsing.
- `tests/api/`: every row of the API table, success and **every** listed error, including headers (`Location`, `ETag`, `X-Request-ID`, `Content-Type: application/problem+json`), archived patients giving 404 everywhere, the note of another patient giving 404, search/filter/sort/pagination combinations, `last_visit` updating after a note is created or deleted, the 412/428 flow, and seed idempotency (running it twice gives the same count).
- Aim for at least 90% line coverage on `src/app` (add `pytest-cov`).

## Dockerfile (`apps/api/Dockerfile`)
Multi-stage: a builder stage with `ghcr.io/astral-sh/uv` that copies the uv binary, runs `uv sync --locked --no-dev` into `/app/.venv`, using bytecode compilation and a cache mount. The runtime stage is `python:3.14-slim`, runs as a **non-root** user (uid 10001), copies only the venv, `src` and `migrations` (plus `alembic.ini`), exposes 8000, and runs `CMD uvicorn app.main:app --host 0.0.0.0 --port 8000 --proxy-headers`. Add a `HEALTHCHECK` using Python's `urllib` (there's no curl). The same image must be able to run `alembic upgrade head` (Stage 3 uses it for the `migrate` service). Add a `.dockerignore`. Add a `dev` target that also has the dev dependencies and runs uvicorn with `--reload`. Verify with `docker build`, then run the image against a throwaway Postgres container.

You may add an `openapi` target to the root `Makefile`.
